# V12.4 提前觀察 PRELAUNCH-1

正式雷達同時輸出 `prelaunchWatch` 與既有轉強確認／試單／觀察名單。提前觀察從完整普通股快照独立篩選，不受強勢排名短名單限制。`EARLY_WATCH_ONLY` 不代表買點、不寫入持股、不計入正式可買檔數。

## 入選條件

- 最新三個連續月份營收年增率逐月加速，最新至少 10%，最新營收月份距資料日不超過 80 日。
- 籌碼持續累積二擇一：三個連續週快照中 400 張以上占比逐週增加、100 張以下逐週減少；或近五個已公布交易日法人至少三日買超、五日合計與最近兩日合計皆買超。週資料最新不超過 10 日，法人最新不超過 4 個日曆日。
- 收盤守住上彎 MA20，距 MA20 不超過 6%；10 日漲幅 -5%～8%、20 日 -8%～15%；尚未突破前 20 日高點，量比 0.35～1.5。
- 同產業至少 50% 普通股守住 MA20。產業分類不是細分題材；缺族群資料不能通過。
- 股價不超過既有主要價格上限（預設 200 元）。日量至少既有日量門檻的四分之一，20 日均量與平均成交金額須達既有流動性門檻。這允許量縮整理，但仍要求平日可交易性。
- 快取已有重大事件風險時排除。缺少當日公告核查不能解讀成事件全數安全。

`missingInputCounts` 和 `rejectionCounts` 明確呈現全市場缺漏及淘汰原因。任一籌碼分支通過即可，未使用的分支仍列缺資料。不得以單月、單週、單日買超冒充持續性。

## 資料與成本

重用月營收、TDCC、每日因子快取；純篩選與唯讀預覽不增加外部 API 呼叫。原有 TDCC CSV 已涵蓋全市場，現在保存全部四碼普通股，使未曾入選股票也能累積週歷史。原有法人查詢額外保存逐日淨額，不另發請求。基本面仍沿用每週更新。

舊快取可能沒有三個連續月份營收／三週持股／逐日法人資料。缺資料時不虛構候選。正式雷達另為量價與族群條件已通過的整理股補建缺漏歷史，每次最多 20 檔、全日最多 40 資料集請求。營收取足夠去年同期的歷史計算年增率，缺去年同期不補零。逐日法人取近 14 日並合併法人類別。同檔營收補建至少隔 7 日才重試，法人每日只嘗試一次；重复執行不重新消耗額度。保留原官方營收及既有完整因子，不覆蓋為稀疏歷史。`prepare_v12_prelaunch_history` 可獨立補建， 不執行正式雷達。資料源失敗仍報缺漏，不能用缺資料證明沒有機會。

## 確認與驗證

觀察日之前 20 日高點的下一跳價格為參考確認門檻。後續收盤超過門檻且量比至少 1.2，才標記發動；實際進場仍需重新產生合法買價與風險計畫。

每次正式雷達保存獨立 `prelaunch_watch` 及 combined configuration 的完整觀察快照。依本版本每檔首次入選日去重，追蹤 5／10／20 交易日收盤報酬、最高漲幅、最大回撤、幾個交易日後確認突破、20 日仍未發動比例。滿 20 日才計入發動率，未滿樣本為等待。此為觀察價報酬，不能混成實際交易勝率。反覆入選不重設第一次觀察價格。只驗證部署後前瞻紀錄，不拿現在快取製造歷史訊號。

`get_v12_prelaunch_preview` 為唯讀查詢，不保存雷達、不刷新外部因子。正式雷達與收盤作業仍分離。

確認買點若高於可買上限、低於／等於失敗價，`confirmationEntry.executable=false` 並附取消理由，保留原始上限與失敗價。回測也檢查確認觸發價、實際成交收盤价及滑價後成交價，不得突破上限；執行模型版本升為 NET-EXECUTION-3，防止混用旧回測結果。
